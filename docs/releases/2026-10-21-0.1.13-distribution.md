## Windows upgrade on a real machine

Windows 11 (build 26100+) over SSH. The SSH shell runs at High integrity, which
neither reproduces the locked-folder error nor reaches the signed-in session,
so each step ran as a one-shot scheduled task for the same user, interactive,
`RunLevel Limited` (Medium integrity, session 1), removed afterwards. No
firewall, Defender, service or registry edits by hand.

Starting state: `current.json` 0.1.12; the 0.1.12 server started from its own
launcher served port 43121 (`/api/updates` 0.1.12-windows-beta.1); an idle
0.1.11 capture (PID 15952, `audio_recording: false`) in session 1; HKCU Run
value `MeetingCopilotCapture` pointing at `versions\0.1.4-windows-beta.1`;
`archive` and `reports` owned by `BUILTIN\Administrators` with a protected ACL.

Upgrade: `irm https://raw.githubusercontent.com/AIAgentLbs/meetontrack/windows-v0.1.13/scripts/windows/install.ps1 | iex`
(SHA-256 `df97bf39...`, byte-identical to the website's `install.ps1`).
It printed "Installed MeetOnTrack 0.1.13-windows-beta.1" and
"MeetOnTrack: http://127.0.0.1:43121"; the scheduled task reported exit 1
after that output.

- Port 43121 is served by `versions\0.1.13-windows-beta.1\python\pythonw.exe`
  in session 1; `/api/health` and `/api/updates` report 0.1.13-windows-beta.1.
  The old 0.1.12 server is gone.
- The idle 0.1.11 capture was not stopped. Asked `record quit-when-idle` by the
  0.1.13 capture, it answered exit 1 (that recorder has no such command), so
  as designed it stays until the next sign-in, when the Startup shortcut
  (now naming `versions\0.1.13-windows-beta.1\meeting-copilot.ps1`) starts

  and `reports.inaccessible-20261021-215924` (still owned by Administrators,
