# Public MeetOnTrack 0.1.16 distribution acceptance

Date: 2026-10-23. Downloadable technical beta, not a stable/hardware-certified
release. Owner approved installing on the owner's Mac and publishing after the
check ("инсталируй на Mac, да, если все окей. И публикуй тоже"). Same process
as [0.1.15](2026-10-22-0.1.15-distribution.md); this record lists what differs.

## Why four builds

Candidates 1-3 were installed on the owner's Mac before publication and each
exposed a defect that was fixed first: report PDF printing timed out and
retried silently (MEETONTRACK-98), and rebuilding old meetings' reports
revived a week-old, already closed delivery failure as a new problem
(MEETONTRACK-99). Only candidate 4 was published.

## Immutable package identity

Both packages embed application revision
`3b3aa32`, built from a clean detached worktree. `capture/` is byte-identical
to the third candidate, so its Swift release binary was reused.

`f82a0ac157c1b0196952639423341784b80723ae`; Mac notes and `v0.1.16` tag/target

## Owner Mac update

Installed before publication from the exact archive (local file URL with its
SHA pin) while no call was recording. Version 0.1.16, `config.json`
unchanged, Capture relaunched. The delivery indicator shows no open issues
(the revived 2026-10-16 failure cleared on the first health check without
editing any file). No report file changed and nothing was sent after the
install. 63 meetings, 43 with reports.

## Website

Website commit `f1ee82f` (comparison build and tests, `check-project-site.cjs`
and `test_installer.py` 13 tests passed). Live within about 30 seconds:
`install.sh` is byte-identical to the app's at `6130fdc` and shows `v0.1.16`
and the Mac SHA; `install.ps1` is byte-identical to `f82a0ac` and shows

Still pending: the Windows machine runs 0.1.13. The runner acceptance above

## Explicit limits

No clean Mac and no audio hardware tests. Mac is ad-hoc signed and not
notarized; Windows is unsigned. No automatic installer is enabled. Never
restart an active recording to update.
